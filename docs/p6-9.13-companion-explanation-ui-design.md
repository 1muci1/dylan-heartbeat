# P6-9.13 Companion Center Explanation UI Design

## 1. 背景与目标

P6-9.13 已提供以 Delivery ID 为锚点的只读 Explanation contract、认证 GET API 和 MCP Tool。本阶段只设计 Companion Center 中的只读 Explanation 页面，让用户查看一次主动交付已经存在且可以证明的结构化事实。

页面不生成新的解释，不推断缺失事实，不改变任何业务状态。数据唯一来源是现有接口：

```text
GET /api/v1/proactive/explanations/:deliveryId
```

本设计不授权进入实现阶段。

## 2. 页面入口

### 2.1 Companion Center 入口

在 Companion Center 增加“主动互动解释”只读入口，进入独立 Explanation 页面。入口本身不自动请求数据，也不显示最近 Delivery，避免为页面新增列表或聚合数据源。

页面支持两种进入方式：

1. 普通入口：用户进入页面后输入 Delivery ID，并显式点击“查询解释”。
2. 深链入口：`proactive-explanation.html?deliveryId=<encoded-id>`。页面读取并校验 ID 后仍由用户显式触发查询；不在后台自动轮询。

若未来已有的 Proactive Delivery 列表 UI 提供 Delivery ID，可增加“查看解释”链接到同一深链。该链接只负责导航，不携带 Delivery 正文、token 或其他业务字段，也不属于本阶段的前置条件。

### 2.2 页面状态

页面具有以下互斥状态：

- 初始：说明用途并显示 Delivery ID 输入框。
- 加载中：禁用重复查询按钮，显示“正在加载解释”。
- 成功：显示字段白名单内的结构化事实。
- 未找到：显示 Delivery 不存在或不可访问的空状态。
- 认证未配置：引导用户前往现有设置页配置 Gateway 地址和 Bearer Token。
- 请求失败：显示安全、可重试加载的错误状态；“重新加载”仅重复 GET 查询，不是 Delivery Retry。

页面不自动刷新、不轮询、不缓存完整 Explanation 响应，也不把 Delivery ID 写入长期业务数据。

## 3. 数据来源与请求边界

### 3.1 唯一数据来源

页面只调用：

```text
GET {configuredGatewayBaseUrl}/api/v1/proactive/explanations/{encodeURIComponent(deliveryId)}
Authorization: Bearer {existingConfiguredToken}
Cache-Control behavior: browser request uses cache: no-store
```

禁止调用或组合以下数据源：

- Delivery Store、EventStore、AI Job Store、Feedback Store 或数据库。
- Proactive Overview、Delivery list/detail、Wake Decision、Memory、State 或 Relationship API。
- MCP Tool、模型、外部服务或 Android Device Channel。
- 浏览器中推断、拼接或补全的历史事实。

页面只接受单个 Delivery ID。ID trim 后必须为 1～200 个字符，使用 `encodeURIComponent` 作为一个路径段；不得接受调用方提供完整 URL、HTTP method、query 参数或请求 headers。

### 3.2 是否需要新 API

不需要。现有 Explanation GET API 已提供页面所需的完整公共 schema、404 和安全错误响应。

本阶段不得新增列表、搜索、批量查询、写接口或前端专用聚合接口。若未来产品要求从 UI 浏览 Delivery，再另行定义独立阶段和数据边界。

## 4. 前端认证

需要复用前端现有认证，不新增认证机制。

- 从现有 `AppConfig` Provider 配置读取 Gateway base URL。
- 只在配置类型为 bearer 且 token 非空时发送现有 `Authorization: Bearer` header。
- 缺少 base URL 或 token 时不发请求，显示配置引导。
- 不在 DOM、页面文案、URL、日志、错误或测试快照中展示 token。
- 不把 token 复制到新的 storage key，也不要求管理员 Basic Auth。
- Service Worker 继续绕过带 `Authorization` 的请求和 `/api/` 请求，不缓存 Explanation 响应。

该 Bearer 认证是现有 Gateway 访问认证，不是 Approval。Explanation 查询没有 Approval 流程。

## 5. 展示字段

页面仅展示现有 Explanation API 返回的公共字段。

### 5.1 顶部摘要

- `deliveryId`：显示为可换行的标识，不构造外部链接。
- `summaryCode`：映射为稳定的用户文案：等待发送、发送中、已发送、发送失败、已取消。

未知 `summaryCode` 不自行猜测，整体进入“解释数据不可用”状态。

### 5.2 Delivery

- `delivery.status`
- `delivery.channel`
- `delivery.reasonCode`
- `delivery.attemptCount`
- `delivery.createdAt`
- `delivery.sentAt`
- `delivery.failedAt`
- `delivery.lastErrorCode`

时间可做本地化格式展示，但不得改变或反推业务含义。`null` 时间显示“无记录”。`lastErrorCode` 只显示稳定 code，不扩展成 provider error message。

### 5.3 AI Job

仅在 `aiJob.available === true` 时展示：

- `aiJob.id`
- `aiJob.status`

### 5.4 Trigger Event

仅在 `triggerEvent.available === true` 时展示：

- `triggerEvent.eventType`
- `triggerEvent.occurredAt`

### 5.5 Wake Decision

仅按 API 返回的 availability 展示。当前 contract 要求 `wakeDecision.available === false`，页面显示不可用说明，不展示或推断 decision/reasonCode，也不提供修改入口。

### 5.6 Feedback

`feedback` 非空时展示：

- `feedback.feedbackType`
- `feedback.createdAt`

`feedback === null` 时显示“尚无明确反馈”，不得推断用户态度。

所有动态文本使用 DOM `textContent` 等安全文本接口，不使用 `innerHTML` 注入 API 内容。

## 6. `available:false` 展示规则

对 `aiJob`、`triggerEvent` 和 `wakeDecision` 使用一致规则：

- 显示该分区标题和中性状态“暂无可用关联”。
- 可附加固定说明“当前没有可证明的关联事实”。
- 不展示对象中的其他值；即使异常响应同时包含非空字段，也不渲染。
- 不把 unavailable 显示为系统失败、权限不足或业务否定结论。
- 不用其他字段推断缺失值，不请求第二个 API 补齐。

`feedback === null` 使用单独的“尚无明确反馈”文案，因为 Feedback 不是 availability 对象。

## 7. 404 与错误展示规则

### 7.1 404

HTTP 404 或 `DELIVERY_NOT_FOUND` 显示专用空状态：

- 标题：“未找到该 Delivery”。
- 说明：“请检查 Delivery ID 后重新查询。”
- 保留输入框，允许更正 ID。
- 不显示响应原文、内部 ID 关联、URL 或 stack。

404 不回退调用 Delivery、Event 或其他 API。

### 7.2 认证错误

- 401/403 或 `UNAUTHORIZED`：显示“Gateway 认证失败，请检查现有连接设置”。
- `GATEWAY_KEY_MISSING`/503：显示“Explanation 服务暂时不可用”。
- 不显示或记录 token、Authorization header 或服务器原始响应。

### 7.3 其他错误

- 网络失败、非 JSON、5xx、非法 schema 或未知枚举统一显示“Explanation 暂时不可用，请稍后重新加载”。
- 页面不得展示 provider response、错误 stack、请求 URL、原始 response body 或内部异常 message。
- 已成功显示的数据在下一次查询失败后应清空，避免把旧 Delivery 的解释误认为当前结果。
- “重新加载”仅再次执行同一个只读 GET，不执行 Retry、Cancel、Send 或任何业务命令。

## 8. 禁止展示字段

即使响应异常携带以下字段，页面也不得读取或渲染：

- Delivery 正文 `text`、`dedupeKey`、内部 `jobId`、`eventId`。
- Worker/Retry 字段：`lockedAt`、`lockOwner`、`nextRetryAt`、`maxAttemptCount`。
- AI Job input/output、prompt、provider、model、usage、token 统计、error message、stack。
- Event payload、source、correlation/causation、内部去重字段。
- Feedback ID、评论或额外用户行为细节。
- Memory content、聊天全文、模型 reasoning。
- API/Bearer token、Authorization header、Gateway 内部配置。
- URL、SQL、数据库字段、provider response 或服务器 stack。
- contract 白名单之外的任意未知字段。

前端应显式选择字段构造 DOM，不遍历对象自动生成全部键值。

## 9. 明确不包含的能力

本阶段不包含：

- Delivery Retry，包括人工或自动重试。
- Delivery Cancel。
- 主动消息 Send 或 resend。
- Reminder Draft、Reminder 检查、系统 Reminder/Alarm/Calendar 或任何 Reminder 操作。
- Wake Decision 修改、重算、补写、推断或 Rollout/Gate 调整。
- Feedback 写入或修改。
- Explanation 模型生成、自然语言扩写或聊天问答。
- Approval、Audit write Event、State/Memory 写入或 Device Command。
- Android Companion 变化。

页面中不得出现上述操作按钮、隐藏 action、快捷键或可调用 endpoint。

## 10. 数据持久化边界

- 不新增 migration、表、字段或索引。
- 不保存 Explanation 响应、查询历史或最近查看列表。
- 不创建 Event、Audit、State 或 Memory。
- 不修改 Delivery、AI Job、Feedback 或 Wake Decision。
- 仅继续使用前端现有 Provider 配置；不新增 token 或业务数据的 localStorage 项。
- 页面生命周期内可以在内存中保存当前渲染数据，切换 Delivery ID 或请求失败时清空。

## 11. 测试计划

测试使用静态 fixture、fake fetch 或 Fastify inject；禁止访问真实 Gateway、模型、Bark、设备或外部服务。

### 11.1 页面入口与认证

1. Companion Center 入口指向固定 Explanation 页面。
2. 深链 ID 被 trim、限制 1～200 字符并使用 `encodeURIComponent`。
3. 缺少 Gateway base URL/token 时不调用 fetch，并显示设置引导。
4. 合法请求只使用现有 Bearer 认证和 GET，且设置 `cache: no-store`。
5. 不允许调用方控制 URL、method、headers 或 query string。
6. 页面不自动加载、不轮询。

### 11.2 成功渲染

1. 五种 summary/status 使用稳定文案。
2. 只渲染本设计列出的字段。
3. 时间和 null 值使用稳定展示规则。
4. Feedback 有值和 `null` 均正确显示。
5. 所有 API 文本通过 `textContent` 渲染，不使用 `innerHTML`。
6. 响应注入未知字段、正文、payload、token、provider 或 stack 时 DOM 不包含这些值。

### 11.3 Availability

1. AI Job、Trigger Event、Wake Decision 的 `available:false` 显示中性不可用状态。
2. `available:false` 且响应异常携带非空子字段时不渲染子字段。
3. 页面不调用其他 API 补齐 unavailable 数据。
4. Wake Decision 不出现修改或重算控件。

### 11.4 错误状态

1. 404/`DELIVERY_NOT_FOUND` 显示未找到状态并允许更正 ID。
2. 401/403 显示认证设置提示。
3. 503、5xx、网络失败、非 JSON 和非法 contract 显示统一安全错误。
4. 新查询失败时清除旧结果。
5. 错误 DOM 和测试输出不包含 token、URL、response body、provider message 或 stack。

### 11.5 无副作用与回归

1. 页面代码不存在 POST、PUT、PATCH、DELETE 请求。
2. 页面不存在 Retry、Cancel、Send、Reminder、Feedback write 或 Wake Decision action。
3. 调用前后 Event、State、Memory、Delivery、Feedback 和数据库均不变化。
4. Service Worker 不缓存 `/api/` 或带 Authorization 的响应。
5. 现有 Explanation API/MCP contract、Companion Center 页面和全量 Node 测试保持通过。
6. 实现阶段运行 `npm test` 和 `git diff --check`。

## 12. 设计结论

该 UI 可以在不新增 API、migration 或业务写能力的前提下实现。它复用 Companion Center 现有 Gateway base URL 和 Bearer 认证，只对现有 Explanation GET API 做显式、白名单化的只读展示。

进入实现前仍需明确授权本阶段编号、页面文件范围和验收标准；在此之前保持设计状态，不标记为 `READY`，不修改业务代码。
