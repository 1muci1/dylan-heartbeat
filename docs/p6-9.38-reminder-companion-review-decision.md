# P6-9.38 Reminder Draft Companion Review Decision

## 1. 决策目的

本文对 `p6-9.38-reminder-companion-review-design.md` 中尚未冻结的实现前问题作出决策：

- 本地存储技术。
- 草稿 schema 和生命周期。
- review TTL 与过期规则。
- App 重启行为。
- UI 最小范围。
- 与 command receipt 幂等设计的事务边界。
- Gateway 与 Device Command 是否参与本地 review。

本文只收口设计，不授权实现，不修改 Gateway 或 Android 代码，不新增 migration，也不创建新的 roadmap 阶段。

## 2. 总体决策

Reminder Draft Companion Review 第一阶段采用以下边界：

1. 使用 Android 应用私有 SQLite repository 持久化本地草稿。
2. review 与 Gateway execution idempotency 分阶段实现。
3. Gateway 和 Device Command 只参与既有的 approved draft create。
4. list、detail、reject、expire、cleanup 全部在 Android 本地完成。
5. 草稿状态只允许 `created`、`rejected`、`expired`。
6. review TTL 固定为 7 天，且不得晚于草稿目标时间。
7. rejected/expired 时立即清除 title/time，仅保留最小 tombstone 30 天。
8. 不新增真实 Reminder、Calendar、Alarm、Notification 或后台调度能力。

Review 第一阶段可以在不实现 Gateway 持久化 Approval/execution receipt 的情况下独立交付，但不得声称已经解决 Device Command 重试幂等问题。

## 3. 本地存储决策

### 3.1 选择

选择 Android framework `SQLiteOpenHelper` 管理应用私有数据库。

理由：

- 当前 Android Companion 结构小，没有 Room/KSP/kapt 依赖。
- SQLite 支持原子事务、状态约束和进程重启恢复。
- 不增加外部服务、Android 权限或新 Gradle plugin。
- 后续 command receipt 可以在同一本地数据库中增加独立表并参与事务。

不选择：

- 继续使用进程内 `MutableMap`：无法跨重启。
- SharedPreferences JSON：不适合原子状态转换、排序、过期扫描和后续 receipt 事务。
- 外部存储：违反数据边界。
- Gateway 存储草稿正文：扩大敏感数据范围。

### 3.2 数据库边界

- 数据库必须位于 Companion 应用私有目录。
- `android:allowBackup="false"` 保持不变。
- 不使用 external storage、ContentProvider 或共享文件。
- 不新增 Manifest 权限。
- 数据库不得被日志、debug dump 或网络接口导出。

本文不创建数据库或 migration。实现任务必须按 Android 本地 schema 变更处理初始化、版本升级和失败恢复测试。

## 4. Schema 决策

第一版本地表建议命名：

```text
reminder_drafts
```

字段固定为：

| 字段 | 类型/约束 | 含义 |
| --- | --- | --- |
| `draft_id` | TEXT PRIMARY KEY | 不透明本地 ID |
| `title` | TEXT NULL | 仅 created 时保存，1～120 字符 |
| `target_time` | TEXT NULL | 仅 created 时保存的 UTC ISO 时间 |
| `status` | TEXT NOT NULL CHECK | `created/rejected/expired` |
| `created_at` | TEXT NOT NULL | UTC ISO 时间 |
| `expires_at` | TEXT NOT NULL | UTC ISO 时间 |
| `decided_at` | TEXT NULL | rejected/expired 转换时间 |
| `purge_after` | TEXT NULL | 终态 tombstone 删除时间 |

一致性约束：

- `created`：title、target_time 非空，decided_at、purge_after 为空。
- `rejected|expired`：title、target_time 为空，decided_at、purge_after 非空。
- `expires_at >= created_at`。
- 所有时间写入前规范化为 UTC ISO-8601。
- 不保存 Approval ID、commandId、requestId、payload 或 Gateway metadata。

Repository 公共模型可以将 terminal title/time 表达为 `null`；UI 不应尝试恢复已清除内容。

## 5. TTL 与过期决策

### 5.1 Review TTL

固定：

```text
REVIEW_TTL = 7 days
```

创建时：

```text
expiresAt = min(createdAt + 7 days, targetTime)
```

理由：

- 草稿超过目标时间后继续显示为待检查没有意义。
- 7 天为固定、可预测、可测试的 review 上限。
- 不静默修改原始 targetTime，只计算独立 expiresAt。

若 `targetTime <= createdAt`，创建失败并返回现有安全 invalid code；不得创建立即过期草稿。

### 5.2 过期触发

不使用后台定时器或系统调度。仅在以下时机运行本地 expiry sweep：

- repository 初始化后首次读取。
- MainActivity/草稿页面进入前台。
- list/get 操作前。

规则：

```text
status == created && now >= expiresAt
    -> expired
```

转换必须在单个本地事务中同时：

- 更新 status 为 expired。
- 设置 decidedAt。
- 清空 title 和 targetTime。
- 设置 purgeAfter。

App 未运行期间不声明精确执行过期；`decidedAt` 记录实际 sweep 时间，`expiresAt` 保留规则截止时间。

## 6. Rejected 与终态保留决策

### 6.1 Reject

- 只能由用户在 Companion 前台明确点击并二次确认。
- 只允许 `created -> rejected`。
- 重复 reject 返回当前 rejected，不修改首次 decidedAt/purgeAfter。
- reject 事务立即清除 title/targetTime。
- 不联系 Gateway，不创建 Device Command，不写 Event/State/Memory。

### 6.2 Tombstone retention

固定：

```text
TERMINAL_RETENTION = 30 days
purgeAfter = decidedAt + 30 days
```

Tombstone 仅保留：

- draftId。
- status。
- createdAt、expiresAt、decidedAt、purgeAfter。

不保留 title/time。purge sweep 与 expiry sweep 一样只在前台/repository 访问时运行，不使用后台任务。

物理删除条件：

```text
status in (rejected, expired) && now >= purgeAfter
```

删除不回传 Gateway。Gateway 的 created receipt 是创建事实，不随本地 review 状态更新。

## 7. Repository API 决策

引入单一 `ReminderDraftRepository`，由 Device Command handler 和 UI 共享。最小接口：

```text
create(title, targetTime) -> created draft
listCreated() -> created drafts
get(draftId) -> draft or null
reject(draftId) -> rejected draft
refreshLifecycle() -> expiry/purge counts
```

约束：

- `create`、`reject` 和 lifecycle sweep 使用数据库事务。
- 返回不可变 data class 或副本。
- `listCreated` 按 createdAt DESC、draftId DESC 稳定排序。
- Repository 不接受任意 status update。
- UI 不直接执行 SQL。
- Handler 不维护第二份进程内 Map。
- Repository 异常映射为稳定本地错误，不显示或记录 stack。

现有 `ReminderDraftHandler.create` 应委托同一个 repository；MainActivity/UI 通过同一应用级 composition root 获取 repository。

## 8. UI 范围决策

### 8.1 第一阶段包含

- MainActivity 中的“Reminder 草稿”入口。
- created 数量。
- created 草稿列表。
- 草稿详情。
- 明确的“仅为 Companion 应用内草稿”说明。
- 本地 reject，带二次确认。
- 空列表、加载失败、草稿不存在状态。
- Activity 重建和 App 重启后的恢复。

### 8.2 第一阶段不包含

- rejected/expired 历史列表；终态只需在当前详情更新时显示，之后可以从默认列表移除。
- 编辑 title/time。
- 恢复、接受、安排、执行或发送草稿。
- 手工删除 created 草稿。
- 搜索、分页、同步或导出。
- Notification、Calendar、Alarm 或真实 Reminder 操作。

### 8.3 UI 文案

固定状态文案：

- created：`待检查`
- rejected：`已拒绝，未创建系统提醒`
- expired：`已过期，未创建系统提醒`

页面固定声明：

> 这些内容只是 Companion 应用内草稿，不会创建系统提醒或通知。

禁止出现“确认提醒”“保存到系统”“已安排”“将通知”等文案。

## 9. 重启行为决策

App/Activity 重启后：

1. 打开同一私有数据库。
2. 在首次 list/get 前执行 lifecycle sweep。
3. 保留未过期 created 草稿。
4. 将已到期 created 转为 expired 并清除敏感内容。
5. 保留未到 purgeAfter 的最小终态 tombstone。
6. 不连接 Gateway。
7. 不重发 Device Command。
8. 不重新调用 create。

临时 offline、session expiry、pairing 状态变化不删除本地草稿。若 App 数据被用户清除，草稿丢失是明确的本地数据清除结果；系统不从 Gateway 恢复正文。

## 10. Gateway / Device Command 决策

### 10.1 Gateway

Gateway 仅继续参与现有 approved create 流程。不新增：

- 草稿 list/detail API。
- reject/expire API。
- review Event 或 State。
- MCP Tool。
- 草稿内容同步。

### 10.2 Device Command

Device Command 仅继续使用现有：

```text
reminder.draft_create
```

不新增 list/get/reject/expire/accept action。

Review UI 的 reject/expire 是本地 repository 状态转换，不属于远程设备执行，也不需要新的 Approval。

## 11. 与 command receipt 幂等的事务边界

### 11.1 分阶段决定

Review 第一阶段不实现：

- Gateway persistent Approval。
- Gateway execution receipt。
- Android command receipt 表。
- Device Command 自动 retry/replay。
- outcome unknown reconciliation。

这些继续属于 `p6-9.38-reminder-idempotency-design.md` 的独立候选。

### 11.2 当前创建提交点

Review 实现中，`ReminderDraftHandler.create` 只有在 `reminder_drafts` insert 事务提交后才能返回 `{draftId,status:"created"}`。这样确保成功 acknowledgement 对应可在重启后读取的本地草稿。

该保证不解决 acknowledgement 丢失后的重复 command：在 Android command receipt 未实现前，仍禁止自动重试 Reminder Draft Device Command。

### 11.3 未来兼容

未来 Android command receipt 应使用同一 SQLite 数据库的独立表，并在一个事务中：

```text
insert reminder_drafts
insert command_receipt(commandId -> draftId)
commit
```

本阶段 `reminder_drafts` 不预留 commandId 字段，避免把 protocol metadata 混入用户草稿表。未来本地 migration 必须保持现有 draftId 和生命周期数据。

## 12. 敏感数据与日志决策

允许仅在 Android 私有 `reminder_drafts` 的 created row 中保存 title/time。

禁止在以下位置保存或输出 title/time：

- Gateway database、Event、Audit 或 State。
- command receipt 表。
- Android logcat、异常 message、analytics 或 crash metadata。
- Intent extra、Clipboard、外部文件或可共享 provider。

所有错误日志如确有必要，只允许稳定 error code 和组件名；不得记录 stack、payload、draft content、token 或 response。

## 13. 禁止能力

本决策不允许：

- 自动接受或执行草稿。
- 绕过创建阶段 Approval。
- 模型改变草稿状态。
- AlarmManager、CalendarContract、NotificationManager。
- WorkManager、JobScheduler、Service、Boot Receiver。
- 启动外部 Reminder/Calendar Intent。
- 新 Android 权限。
- 新 Gateway API/MCP/Device action。
- Memory、State 或关系等级变化。

Manifest 必须继续只有 `android.permission.INTERNET`，并保持 `allowBackup=false`。

## 14. 实现验收测试矩阵

### 14.1 SQLite / schema

1. 首次安装创建 schema v1。
2. 空数据库 list 返回空集合。
3. CHECK/应用验证拒绝未知 status 和非法时间。
4. created/terminal 字段一致性约束成立。
5. transaction failure 不留下部分 row。
6. 重复初始化幂等。
7. 私有路径、allowBackup=false、无新增权限。

### 14.2 Lifecycle

1. create 计算 `min(created+7d,targetTime)`。
2. targetTime 不晚于 createdAt 时拒绝。
3. 未到 expiresAt 保持 created。
4. `now == expiresAt` 转为 expired。
5. expire 原子清除 title/time 并设置 decidedAt/purgeAfter。
6. reject 原子清除 title/time。
7. 重复 reject 不改变首次终态 metadata。
8. rejected 不转 expired。
9. 30 天前不 purge，`now == purgeAfter` 删除。

### 14.3 Restart

1. Repository 重建后恢复 created。
2. 离线期间到期的草稿在下一次读取时 expired。
3. terminal tombstone 恢复但不含 title/time。
4. 重启不调用 Gateway、HTTP 或 Device Command。
5. Activity recreation 不重复 create/reject。

### 14.4 UI

1. MainActivity 显示入口和 created count。
2. 列表/详情只读取 repository。
3. 固定草稿免责声明可见。
4. reject 有二次确认；取消不写状态。
5. 详情打开不改变状态。
6. 终态不提供恢复或执行控件。
7. 错误不显示 stack、SQL 或 payload。
8. 小屏、旋转和 TalkBack 标签可用。

### 14.5 Boundary regression

1. 现有 `reminder.draft_create` Approval、schema 和 Provider 输出不变。
2. 成功 response 只在 draft insert commit 后返回。
3. 不新增 Device action、Gateway API 或 MCP Tool。
4. 源码不引用 Alarm/Calendar/Notification/WorkManager/Service。
5. Manifest 仍只有 INTERNET。
6. Node `npm test` 通过。
7. Android JVM tests 与 `assembleDebug` 通过。
8. `git diff --check` 通过。

## 15. READY 判断

本决策已经冻结 review 第一阶段所需的存储、TTL、schema、重启、UI 和 Gateway/Device 边界。技术前置条件具备，可以形成一个严格限定的实现任务。

但 roadmap 当前仍将该方向标为 `NOT_READY`，本文不修改 roadmap、不新增阶段，也不构成实现授权。只有在用户明确指定阶段编号、实现文件范围、Android 本地 schema 变更授权和验收命令后，才能进入实现。
