# P6-9.38 Reminder Draft Integration Design

## 1. 阶段目标

P6-9.38 在现有 Agent Tool Runtime 与 Android Device Command Channel 基础上，增加一个受控的 Reminder Draft 能力：

```text
android.reminder.draft_create
```

该 Tool 只允许在已配对、在线的 Android Companion 中创建一个待用户检查和确认的草稿。它不创建 Android 系统提醒，不安排定时任务，不发送通知，也不在后台执行任何设备操作。

本阶段必须继续使用现有调用链：

```text
Tool Registry
    -> Capability Policy
    -> Approval Flow
    -> Tool Execution Gateway
    -> AndroidDeviceProvider
    -> DeviceAuthorizationGateway
    -> DeviceCommandService
    -> online Android Session
    -> DeviceCommandClient
    -> Companion 内部 Reminder Draft handler
    -> Device Protocol response validation
    -> ToolResultNormalizer
```

## 2. 非目标

P6-9.38 不实现或开放：

- Android 系统 Reminder、Alarm 或 Calendar 写入。
- 到时执行、后台调度、后台 Service 或开机启动。
- 系统通知发送或其他应用通知读取。
- Notification Listener。
- App 启动、关闭、控制或任意 Intent。
- Accessibility、ADB、Root、Device Admin 或屏幕自动操作。
- 联系人、短信、日历、位置、剪贴板或文件读取。
- 通用 `android.execute` 或任意 action/payload 通道。
- 新的 HTTP 写接口、MCP 能力或 Android 权限。
- 模型输出直接改变 Android 或 Gateway 状态。

## 3. Tool 定义

### 3.1 Registry Tool

```json
{
  "name": "android.reminder.draft_create",
  "description": "Create a reminder draft in the paired Android Companion for user review.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "title": {
        "type": "string",
        "minLength": 1,
        "maxLength": 120
      },
      "time": {
        "type": "string",
        "minLength": 1,
        "maxLength": 40
      }
    },
    "required": ["title", "time"],
    "additionalProperties": false
  },
  "permissionLevel": "user_confirm",
  "executionType": "device_bridge"
}
```

### 3.2 Provider Tool metadata

Android Provider 对该 Tool 声明：

- `name`: `android.reminder.draft_create`
- `riskLevel`: `medium`
- `inputSchema`: 与 Registry 定义一致

Registry 和 Provider 的 schema 必须保持一致。Provider 不得放宽字段、长度或格式限制。

### 3.3 Device action

Tool 经过 Provider 映射为唯一 Device Protocol action：

```text
reminder.draft_create
```

不得将 Tool 名称或用户输入转换为任意 Android action。

## 4. 输入 schema 与规范化

### 4.1 输入

```json
{
  "title": "Call Alice",
  "time": "2026-07-23T09:30:00.000Z"
}
```

规则：

- 输入必须是普通 JSON object。
- 只允许 `title` 和 `time` 两个字段。
- `title` 必须是非空字符串，trim 后长度为 1～120。
- `time` 必须是合法、带时区语义的 ISO-8601 时间字符串，长度不超过 40。
- Gateway 或 Provider 将 `time` 规范化为 UTC ISO 字符串后再进入 Device Protocol。
- 不接受 recurrence、联系人、位置、备注、URL、应用包名、Intent、通知内容或任意 payload。
- 所有验证和规范化不得修改调用方输入。

时间已经过去、超出合理产品窗口或 Android Companion 无法展示的情况，应以稳定错误码安全失败；不得静默调整用户时间。具体允许时间窗口在实现任务中通过常量和测试确定。

### 4.2 Command payload

Device Protocol request 的 payload 只能是规范化后的：

```json
{
  "title": "Call Alice",
  "time": "2026-07-23T09:30:00.000Z"
}
```

DeviceCommandStore 不保存该 payload。日志、Audit Event 和错误信息也不得保存或回显完整 title。

## 5. 输出 schema

### 5.1 成功响应

Android Companion 只返回最小结果：

```json
{
  "draftId": "opaque-draft-id",
  "status": "created"
}
```

约束：

- `draftId` 是 Companion 生成的不透明随机标识，不包含 device ID、title、time 或用户信息。
- `status` 在本阶段只能是 `created`。
- `created` 表示 Companion 内已有待用户检查的草稿，不表示系统提醒已创建、已安排或将自动执行。
- Provider 必须先使用 DeviceBridgeProtocol 校验 requestId、success/error 形状和 JSON 安全性。
- 通过协议校验后，Provider 还必须校验本 Tool 的精确输出 schema。
- 最终结果必须经过 ToolResultNormalizer，过滤敏感字段并执行大小限制。

### 5.2 失败响应

对外只暴露稳定、无敏感内容的错误码。至少包括：

- `DEVICE_NOT_AUTHORIZED`
- `DEVICE_OFFLINE`
- `DEVICE_COMMAND_TIMEOUT`
- `DEVICE_COMMAND_FAILED`
- `REMINDER_DRAFT_INVALID`
- `REMINDER_DRAFT_UNAVAILABLE`

协议不匹配、未知字段、错误 requestId、非法 result 或 Android handler 异常统一收敛为 `DEVICE_COMMAND_FAILED`，不得返回 provider response、堆栈或原始 Android 错误。

## 6. 风险等级与 Capability Policy

`android.reminder.draft_create` 的风险等级为 `medium`，permission 为 `user_confirm`。

原因：

- 它把用户提供的内容发送到已配对设备。
- 它在 Companion 内产生用户可见的本地草稿状态。
- 虽然不执行系统提醒，仍属于设备侧写操作。

Capability Policy 必须返回：

```json
{
  "allowed": false,
  "decision": "user_confirm",
  "reasonCode": "TOOL_USER_CONFIRM_REQUIRED"
}
```

Provider、DeviceCommandService 和 Android Companion 均不得将该 Tool 降级为 automatic，也不得因设备已配对而跳过 Approval。

## 7. Approval 生命周期

继续使用现有 Approval Flow 和状态：

```text
pending -> approved
pending -> rejected
pending -> expired
```

流程：

1. Tool Execution Gateway 完成 Tool 查找、Capability Policy 和输入 schema 校验。
2. Gateway 对规范输入生成 canonical input hash。
3. 没有 approvalId 时创建 `pending` Approval，并返回 `TOOL_APPROVAL_REQUIRED`。
4. Approval 只公开安全摘要，不包含完整 title 或 time。
5. 用户明确批准后状态变为 `approved`；拒绝后为 `rejected`；超过 TTL 后为 `expired`。
6. 执行请求必须同时匹配 toolName、approvalId 和 inputHash。
7. rejected、expired、不存在或输入不匹配的 Approval 返回 `TOOL_PERMISSION_DENIED`，不得创建 Device Command。
8. Approval 不是永久设备授权，不能用于其他 Tool、其他输入或其他设备。

当前 Approval Store 没有 `consumed` 状态。P6-9.38 实现必须明确并测试重复提交策略：相同 approvalId 的重复请求不得静默创建多个不同草稿。优先使用与 approvalId/规范输入绑定的幂等执行边界；不得通过扩展为长期授权来解决重复问题。若现有存储无法安全表达该边界，应在实现前单独确认设计，而不是隐式改变 Approval 生命周期。

## 8. Audit 与 Event 行为

Reminder Draft 继续使用现有 ToolAuditStore，通过 EventStore 写入重要生命周期事实。业务模块不得直接写 `events` 表。

建议事件顺序：

```text
tool.requested
    -> tool.approved
    -> tool.completed
```

失败路径：

```text
tool.requested
    -> tool.failed
```

拒绝或过期时保留 Approval 状态事实，不创建 Device Command；若现有 Audit 编排记录该结果，只能使用既有安全事件结构，不临时增加未经定义的 Event 类型。

允许的 Audit/Event payload：

- toolName
- approvalStatus
- success
- 稳定 errorCode
- EventStore 自身的时间、subject 和关联元数据

禁止保存：

- reminder title 全文
- time 原始输入
- Device Protocol payload
- Device response 全文
- approvalId、pairing token、sessionId 或传输凭据
- prompt、聊天全文、Memory 内容、provider response 或 stack

`tool.completed` 只表示草稿创建请求成功完成，不表示真实提醒已执行。Device Command 的 `created/sent/completed/failed` 是短期通道状态，不替代 Tool Audit Event。

## 9. Android Command Channel 调用流程

```text
ToolExecutionGateway.execute()
    |
    | schema + medium risk + matching approved inputHash
    v
AndroidDeviceProvider.execute("android.reminder.draft_create", input)
    |
    | validate and normalize title/time
    v
DeviceAuthorizationGateway.authorize(deviceId, "reminder.draft_create")
    |
    | device exists and status == paired
    v
DeviceCommandService.execute({ deviceId, action, payload })
    |
    | sessionService.assertOnline(deviceId)
    | command: created -> sent
    v
DeviceBridgeProtocol.createRequest()
    |
    v
active Android Session transport
    |
    v
DeviceCommandClient
    |
    | exact action allowlist + exact payload validation
    v
Companion Reminder Draft handler
    |
    | create Companion-local pending draft only
    v
DeviceBridgeProtocol.validateResponse()
    |
    | command: sent -> completed / failed
    v
AndroidDeviceProvider output validation
    |
    v
ToolResultNormalizer
```

调用前必须同时满足：

- Device 存在。
- Device 状态为 paired，revoked 必须拒绝。
- Android Session online 且未过期。
- Tool action 在 Provider、Device Command 和 Android 客户端三层白名单中。
- Approval 与当前规范输入精确匹配。

超时返回 `DEVICE_COMMAND_TIMEOUT`，并将 Command 标记为 failed。离线、撤销或无效响应均不得降级为本地 fake 结果。

## 10. Android Companion 边界

Android 侧只增加 Reminder Draft 的纯应用内 handler 和数据模型。它必须：

- 只接受 `reminder.draft_create`。
- 拒绝未知 action 和额外 payload 字段。
- 不修改调用方 payload。
- 生成不透明 draftId。
- 返回最小、结构化响应。
- 不使用真实 Reminder、Alarm、Calendar、通知或 Accessibility API。
- 不增加 Manifest 权限。
- 不启动后台 Service。
- 不读取设备或其他应用内容。

本阶段的“草稿”必须由用户在 Companion 前台明确检查；任何后续“保存到系统提醒”或“到时提醒”都需要独立 Tool、独立权限设计和新的实现阶段。

## 11. 数据持久化边界

### 11.1 Gateway

- Tool Approval Store 只保存 inputHash、安全摘要和生命周期 metadata，不保存完整输入。
- DeviceCommandStore 只保存 commandId、deviceId、action、status 和时间，不保存 payload 或 response。
- Tool Audit 只通过 EventStore 保存最小事实，不保存 reminder 内容。
- 不写 Memory。
- 不写 Companion State。
- 不修改关系等级。
- P6-9.38 不新增数据库 migration。

### 11.2 Android Companion

- 草稿内容只存在于 Companion 的受限草稿边界内，不上传为 Gateway 长期数据。
- 本阶段不承诺跨重启持久化；若实现只使用进程内 fake/in-memory store，必须在 UI 和测试中保持“草稿原型”语义。
- 若未来要求设备本地持久化，必须单独定义加密、删除、过期和用户可见管理策略，不在 P6-9.38 隐式加入。

### 11.3 日志

Gateway 和 Android 日志均不得记录：

- title 或完整 payload
- sessionId、approvalId、pairing token 或认证 header
- Device response 全文
- prompt、聊天全文、Memory 内容或 stack

## 12. 实现阶段测试要求

后续实现至少覆盖：

- approved、paired、online Device 成功创建 draft。
- 无 Approval、rejected、expired 和 inputHash 不匹配时拒绝。
- pending、revoked、offline 和 expired Session 拒绝。
- 非法 title/time、额外字段和未知 action 拒绝。
- Device Command timeout。
- requestId 不匹配和非法 response 拒绝。
- Device Command Store 不保存 payload/response。
- Audit/Event 不保存 title/time。
- Provider 结果经过 Device Protocol 和 ToolResultNormalizer。
- 输入不可变。
- 重复 approvalId/相同输入不会创建非预期的重复草稿。
- Android 使用 fake handler，不调用真实 Android 服务。
- Manifest 权限仍只有 INTERNET。
- 完整 Tool Execution Gateway 链路。
- `npm test` 全量回归。
- Android JVM 单元测试与 debug build（构建环境可用时）。

## 13. 当前结论

P6-9.38 只扩展现有受控 Tool Runtime 与 Device Command Channel，使 Android Companion 能创建待用户确认的 reminder draft。它不执行提醒、不发送或读取通知、不控制 App、不使用 Accessibility/ADB、不增加后台服务，也不扩大 Memory、State、Event、HTTP 或 MCP 权限边界。

任何真实系统提醒执行能力必须作为后续独立阶段重新进行 Tool schema、风险、Approval、Android 权限和 Audit 设计。
